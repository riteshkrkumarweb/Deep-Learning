# Attention Mechanism 

##  Why Attention Is Needed

The traditional Encoder–Decoder architecture has two main limitations:

1. **Encoder-side problem:** The encoder must summarize the entire input sentence into a fixed-size representation. Longer sentences place more information pressure on this representation.
2. **Decoder-side problem:** The same static representation is supplied throughout decoding, even though different output words require different parts of the input.

**Core idea:** Attention lets the decoder dynamically focus on the encoder time steps that are most useful for the current output time step.

##  Architecture Review

- **Encoder:** Processes the input sentence step by step and produces hidden states.
- **Decoder:** Generates the output sentence step by step.
- The transcript describes LSTM cells in the Encoder–Decoder architecture.
- In the original paper discussed in the transcript, the encoder uses a **Bidirectional LSTM**; the decoder is not described as bidirectional.

##  Important Terms

| Term | Meaning in the transcript |
|---|---|
| Encoder hidden state | Information produced by the encoder at an input time step |
| Decoder hidden state | The decoder's internal state at a decoding time step |
| Decoder output token | The token generated by the decoder; during teacher forcing, the correct previous target token can be supplied as input |
| Context vector / attention input | A weighted combination of encoder hidden states for the current decoder step |
| Alignment score / attention weight | A value indicating how much an encoder time step contributes to the current decoder step |

##  Decoder Inputs

At each decoding step:

- **Traditional Encoder–Decoder:** The previous output token and previous decoder state.
- **Attention-based Encoder–Decoder:** The previous output token, previous decoder state, and a context vector.

The context vector provides encoder information relevant to the current decoding step.

##  Context Vector

The context vector is created by multiplying each encoder hidden state by its attention weight and adding the results together.

- Attention weights are scalar values.
- Encoder hidden states are vectors.
- The context vector has the same dimensionality as the encoder hidden states in the formulation described in the transcript.

##  Alignment Scores / Attention Weights

The transcript explains that an alignment score depends on two things:

- The encoder hidden state being considered.
- The previous decoder hidden state.

A trainable artificial neural network (ANN) calculates the score in the alignment model described in the video. The network's parameters are learned together with the encoder and decoder through backpropagation through time.

The score indicates how useful an encoder time step is for generating the current output.

##  Repeated Attention Process

At each decoder time step:

1. Use the previous decoder state.
2. Compare it with each encoder hidden state to calculate alignment scores.
3. Obtain attention weights.
4. Calculate the context vector as a weighted sum.
5. Supply the context vector, previous decoder state, and previous output token to the decoder to help generate the next output.
6. Repeat for the next output step.

##  Attention Matrix

If there are four encoder time steps and four decoder time steps, there are sixteen attention weights.

The weights can be plotted as a matrix or heatmap to inspect alignments between input and output words. The original paper discussed in the video visualized English-to-French translation alignments.
